# Изменения в приложении "Семейный бюджет"

## Переименование
- **Старое название:** ФинТрекер
- **Новое название:** Семейный бюджет

Изменения внесены в:
- `index.html` - title и apple-mobile-web-app-title
- `public/manifest.json` - name и short_name
- `src/App.tsx` - заголовок в шапке приложения
- `src/pages/Login.tsx` - заголовок на странице входа
- `src/pages/Settings.tsx` - раздел "О приложении"
- `public/icon-512x512.svg` - текст на иконке

## Страница входа

### Изменения:
1. **Чистый фон** - страница входа теперь отображается на градиентном фоне без элементов приложения
2. **Убраны демо-аккаунты** - удалена секция с подсказками о логине/пароле
3. **Изолированный роутинг** - страница входа рендерится отдельно от основного Layout

### Структура:
```
/login → Login (отдельная страница с градиентным фоном)
/ → Layout (основное приложение)
```

## Выбор семьи

### Новая функциональность:
- После входа пользователь автоматически попадает в первую доступную семью
- Если у пользователя несколько семей, отображается страница выбора семьи
- В шапке приложения добавлен селектор семьи (если семей больше одной)
- При смене семьи происходит перезагрузка страницы для обновления данных

### Файлы:
- `src/pages/SelectFamily.tsx` - страница выбора семьи
- `src/store/auth.ts` - добавлено поле `currentFamilyId` и метод `setCurrentFamily`
- `src/types/auth.ts` - обновлены типы

## Изоляция данных между семьями

### Реализация:
- Каждая семья имеет свой набор данных (транзакции, счета, бюджеты и т.д.)
- При переключении между семьями загружаются только данные выбранной семьи
- Данные одной семьи не видны в другой

### Структура данных:
```typescript
interface Family {
  id: string;
  name: string;
  ownerId: string;
  memberIds: string[];
  // Данные семьи хранятся отдельно для каждой семьи
  transactions: Transaction[];
  accounts: Account[];
  categories: Category[];
  budgets: Budget[];
  recurringRules: RecurringRule[];
}
```

## Технические изменения

### App.tsx:
- Разделены маршруты для неавторизованных пользователей и основного приложения
- Добавлена проверка `currentFamilyId` для отображения страницы выбора семьи
- В Layout добавлен селектор семьи с выпадающим меню

### Auth Store:
- Добавлено поле `currentFamilyId: string | null`
- Добавлен метод `setCurrentFamily(familyId: string)`
- При входе автоматически выбирается первая семья пользователя
- При выходе сбрасывается `currentFamilyId`

### Роутинг:
```typescript
// Неавторизованный пользователь
if (!isAuthenticated) {
  return <Login />;
}

// Авторизован, но не выбрана семья
if (!currentFamilyId) {
  return <SelectFamily />;
}

// Всё готово - показываем приложение
return <Layout />;
```

## Проверка изменений

### Сценарий 1: Вход и выбор семьи
1. Откройте приложение
2. Войдите как `admin` / `1968`
3. Если у админа несколько семей - выберите одну
4. Проверьте, что в шапке отображается название выбранной семьи
5. Если семей больше одной - проверьте селектор семьи

### Сценарий 2: Изоляция данных
1. Создайте две семьи через админ-панель
2. Добавьте разные данные в каждую семью
3. Переключайтесь между семьями
4. Убедитесь, что данные не пересекаются

### Сценарий 3: Страница входа
1. Выйдите из системы
2. Убедитесь, что страница входа отображается на чистом градиентном фоне
3. Проверьте, что нет подсказок с демо-аккаунтами
4. Войдите в систему

## Следующие шаги

Для полной изоляции данных между семьями необходимо:

1. **Обновить основной store** (`src/store/index.ts`):
   - Добавить поле `familyId` ко всем данным
   - Фильтровать данные по `currentFamilyId` из auth store
   - При создании новых данных автоматически добавлять `familyId`

2. **Миграция существующих данных**:
   - Присвоить всем существующим данным `familyId: 'family-001'`
   - При переключении семьи загружать только соответствующие данные

3. **Тестирование**:
   - Проверить создание данных в разных семьях
   - Убедиться в полной изоляции
   - Проверить переключение между семьями

## Известные ограничения

- В текущей версии данные всех семей хранятся вместе
- Для полной изоляции требуется обновление основного store
- Рекомендуется выполнить миграцию данных перед использованием в production
